Twitch Bowl: how it works, and how to build it

Version 2

A stream overlay where a bowl fills with balls, one for each follow, sub, cheer and first-time chatter, and shatters when it's full. This guide assumes you know almost nothing about code.

The three files: bowl.html (the overlay and its editor), MIXITUP_SETUP.md (putting it on stream) and this guide.

Part 1. The big picture

The pieces

PieceWhat it isIts job here

How an event reaches the bowl

1. TwitchA viewer follows, subs, cheers or chats.
2. Mix It UpIt's logged into your channel and sees the event.
3. The widgetMix It Up calls a function in the bowl: Follow(data) by itself, or addBalls({ count: "1" }) from an event command.
4. The countThe function adds to the ball count and saves it in localStorage.
5. The pictureThe game sees the count is higher, drops a ball, and Matter.js makes it fall. OBS shows it.

The bowl never talks to Twitch itself, so there's no login, no keys and no server. Mix It Up does that part.

Version 2: the fun extras

Each new ball can show who sent it, balls are coloured by event (follows, subs, bits, first chats) and keep their colour after a reload, viewers can shake the bowl (great as a channel point reward), there are sounds made by the browser itself, confetti when it breaks, and an optional counter. All of them are under Fun in the editor, and Part 3 explains the code behind each one.

One file, two jobs

bowl.html holds two programs that share most of their code:

  • The overlay: just the canvas. It runs in Mix It Up (and so in OBS). Its settings come from the file itself.
  • The editor: the canvas plus a panel. It opens when you double-click the file. Its settings are saved in your browser while you work, and written into a new copy of the file when you press Save a copy, Copy for Mix It Up or Download Mix It Up widget.

The rule: #edit at the end of the address means editor and #overlay means overlay. Without either, a file opened in a normal browser window is the editor, and anything else (inside Mix It Up, inside OBS, a web address) is the overlay.

Why copies? Each browser has its own notebook. Chrome, where you edit, and OBS, where the overlay runs, can't read each other's. So settings travel inside the file. The ball count stays in OBS's notebook, so changing the bowl never resets it.

Two ways Mix It Up can call the bowl

Widget events (the easy way): a Custom widget has tick boxes for Follows, Twitch Subscriptions, Twitch Bits and Chat Messages. When one is ticked, Mix It Up calls a function with a fixed name: Follow, Subscription, TwitchBits… The downloaded widget file comes with them ticked.

Run Widget Function (the flexible way): any Mix It Up command can include Overlay → Run Widget Function, naming a function such as addBalls plus named parameters. Mix It Up fills in special identifiers like $bitsamount, then calls addBalls({ count: "5" }): one object, every value as text. Use this for chat commands, or for your own rules.

Part 2. Build it yourself

Nine steps from an empty file to a working bowl that Mix It Up can drive. After each step you can open the file and see something new work. Your version will be simpler than bowl.html: fewer settings and a plainer editor. The ideas are the same, and Part 3 explains the full version.

How to follow along. Each step says where each piece goes, then shows it. Copy it exactly, including the punctuation. If something doesn't work, open "The whole file after step N" and compare, or copy that whole file over yours. Press F12 and click Console to see error messages; the line number in an error tells you where to look.

Step 2. A falling ball

Now let a physics engine move the balls. Matter.js works out gravity, bouncing and collisions for you; you just tell it what exists, then draw what it says.

Load Matter.js. Put this line straight under <!-- LIBRARIES GO HERE -->:

<script src="https://cdn.jsdelivr.net/npm/matter-js@0.20.0/build/matter.min.js"></script>

Delete the test circle (from // A test down to context.fill();) and put this in its place:

// The physics engine and the balls in it.
const { Engine, Bodies, Body, Composite } = Matter;
const TICK = 1000 / 60; // Milliseconds per physics step: 60 steps a second
const BALL_SIZE = 30;
const engine = Engine.create();
const balls = new Set();

function dropBall(x, y) {
  const ball = Bodies.circle(x, y, BALL_SIZE / 2, { restitution: 0.3, friction: 0.02 });
  balls.add(ball);
  Composite.add(engine.world, ball);
}

function step() {
  Engine.update(engine, TICK);
  for (const ball of balls) {
    // Off the bottom of the stage: gone for good.
    if (ball.position.y > SIZE + BALL_SIZE) {
      balls.delete(ball);
      Composite.remove(engine.world, ball);
    }
  }
}

function draw() {
  context.clearRect(0, 0, SIZE, SIZE);
  context.fillStyle = 'orange';
  for (const ball of balls) {
    context.beginPath();
    context.arc(ball.position.x, ball.position.y, BALL_SIZE / 2, 0, Math.PI * 2);
    context.fill();
  }
  requestAnimationFrame(draw);
}

setInterval(step, TICK);
requestAnimationFrame(draw);

// A test: a new ball every second, somewhere near the middle.
setInterval(() => dropBall(400 + (Math.random() - 0.5) * 200, 30), 1000);

Open it: refresh. A ball appears near the top every second and falls off the bottom. (This step loads Matter.js from the internet. Step 9 copies it into the file instead.)

  • Bodies.circle makes a ball the engine knows about. restitution is bounciness (0 = dead, 1 = super-ball). Composite.add puts it into the world.
  • step() moves time forward by one sixtieth of a second. setInterval(step, TICK) runs it 60 times a second.
  • draw() wipes the canvas and paints every ball where the engine says it is. requestAnimationFrame(draw) asks the browser to call draw just before the next screen refresh. draw asks again at its end, so it keeps redrawing smoothly, about 60 times a second.
  • Physics and drawing are separate on purpose: the engine decides where things are, the drawing only shows them.
  • Try: change 1000 in the last line to 100: ten balls a second. Change restitution: 0.3 to 0.9: they bounce like rubber.

Step 3. Walls from an outline

A bowl is just a line of points. Each stretch between two points becomes a thick, invisible wall on the outside of the line, so balls rest exactly on the line you see.

Add this just above // A test: a new ball every second:

// The bowl's outline: points along the inside of the bowl, from the left rim to the right rim.
const OUTLINE = [
  [104, 420], [110, 486], [127, 549], [154, 607], [191, 658], [236, 699], [287, 730], [342, 750],
  [400, 756],
  [458, 750], [513, 730], [564, 699], [609, 658], [646, 607], [673, 549], [690, 486], [696, 420],
];
const WALL = 40; // How thick the hidden walls are

// The space inside the outline. Its sign (+ or -) shows which way round it was drawn.
function signedArea(outline) {
  let area = 0;
  outline.forEach(([x1, y1], i) => {
    const [x2, y2] = outline[(i + 1) % outline.length];
    area += x1 * y2 - x2 * y1;
  });
  return area / 2;
}

// One thick wall behind each stretch of the outline.
function makeWalls(outline) {
  const walls = [];
  const outward = signedArea(outline) < 0 ? 1 : -1;
  for (let i = 1; i < outline.length; i++) {
    const [x1, y1] = outline[i - 1];
    const [x2, y2] = outline[i];
    const length = Math.hypot(x2 - x1, y2 - y1);
    if (!length) continue;
    const alongX = (x2 - x1) / length;
    const alongY = (y2 - y1) / length;
    // Overlap at the joints so there are no gaps. The two ends stay flush with the line.
    const before = i > 1 ? WALL / 2 : 0;
    const after = i < outline.length - 1 ? WALL / 2 : 0;
    const shift = (after - before) / 2;
    const x = (x1 + x2) / 2 + alongX * shift - outward * alongY * WALL / 2;
    const y = (y1 + y2) / 2 + alongY * shift + outward * alongX * WALL / 2;
    walls.push(Bodies.rectangle(x, y, length + before + after, WALL, {
      isStatic: true,
      angle: Math.atan2(y2 - y1, x2 - x1),
      friction: 1,
    }));
  }
  return walls;
}

let walls = makeWalls(OUTLINE);
Composite.add(engine.world, walls);

Replace the whole step function with this one. It adds a speed limit:

function step() {
  Engine.update(engine, TICK);
  // A ball may move at most this far in one step, so it can't jump straight through a wall.
  const maxSpeed = 0.75 * (BALL_SIZE / 2 + WALL / 2);
  for (const ball of balls) {
    if (ball.speed > maxSpeed) Body.setSpeed(ball, maxSpeed);
    // Off the bottom of the stage: gone for good.
    if (ball.position.y > SIZE + BALL_SIZE) {
      balls.delete(ball);
      Composite.remove(engine.world, ball);
    }
  }
}

Replace the whole draw function, so you can see the outline:

function draw() {
  context.clearRect(0, 0, SIZE, SIZE);
  // The outline, in purple
  context.strokeStyle = '#a970ff';
  context.lineWidth = 6;
  context.beginPath();
  OUTLINE.forEach(([x, y], i) => (i ? context.lineTo(x, y) : context.moveTo(x, y)));
  context.stroke();

    context.fill();

Open it: a purple bowl shape, and balls piling up in it.

  • makeWalls walks along the outline two points at a time. For each stretch it works out the middle, the length and the angle, then pushes the rectangle WALL / 2 outwards so its inner face sits on the line. signedArea tells it which side "outwards" is, so the outline works whichever way round you draw it.
  • isStatic: true means "never moves": gravity doesn't pull walls.
  • The speed limit matters. Matter.js moves things in jumps, one step at a time. A ball moving faster than the wall is thick could jump from one side to the other without ever touching it. That's why the walls are thick and the speed is capped.
  • Try: change WALL = 40 to WALL = 4 and the drop rate to 100: some balls escape through the bottom. Put it back.

let ballSprite = null;

function loadImage(src) {
  return new Promise((resolve, reject) => {
    const image = new Image();
    image.onload = () => resolve(image);
    image.onerror = reject;
    image.src = src;
  });
}

// Crops the ball picture to a circle once, so any picture makes a round ball.
function makeBallSprite(image, size) {
  const sprite = document.createElement('canvas');
  sprite.width = sprite.height = size * 2;
  const painter = sprite.getContext('2d');
  painter.arc(size, size, size, 0, Math.PI * 2);
  painter.clip();
  const scale = size * 2 / Math.min(image.width, image.height);
  const width = image.width * scale;
  const height = image.height * scale;
  painter.drawImage(image, size - width / 2, size - height / 2, width, height);
  return sprite;
}

function signedArea(outline) {
  let area = 0;
  outline.forEach(([x1, y1], i) => {

  const walls = [];
  const outward = signedArea(outline) < 0 ? 1 : -1;
  for (let i = 1; i < outline.length; i++) {
    const [x1, y1] = outline[i - 1];

function signedArea(outline) {
  let area = 0;
  outline.forEach(([x1, y1], i) => {

function makeWalls(outline) {
  const walls = [];
  const outward = signedArea(outline) < 0 ? 1 : -1;
  for (let i = 1; i < outline.length; i++) {
    const [x1, y1] = outline[i - 1];
    const [x2, y2] = outline[i];
    const length = Math.hypot(x2 - x1, y2 - y1);

    const alongX = (x2 - x1) / length;

  let area = 0;

  const walls = [];

  for (let i = 1; i < outline.length; i++) {
    const [x1, y1] = outline[i - 1];
    const [x2, y2] = outline[i];

function centroid(points) {
  const x = points.reduce((sum, point) => sum + point[0], 0) / points.length;

// Cuts a shape in two along a straight line through a point at an angle.
function cutShape(points, [px, py], angle) {
  const normalX = -Math.sin(angle);
  const normalY = Math.cos(angle);
  const side = ([x, y]) => (x - px) * normalX + (y - py) * normalY;
  const left = [];
  const right = [];
  points.forEach((point, i) => {
    const next = points[(i + 1) % points.length];
    const a = side(point);
    const b = side(next);
    if (a >= 0) left.push(point);
    if (a <= 0) right.push(point);
    if ((a > 0 && b < 0) || (a < 0 && b > 0)) {
      const t = a / (a - b);
      const crossing = [point[0] + (next[0] - point[0]) * t, point[1] + (next[1] - point[1]) * t];
      left.push(crossing);
      right.push(crossing);
    }
  });
  return [left, right];
}

    return null;

localStorage is a small notebook each browser keeps for each website. It survives refreshes and restarts. It stores text, so objects go in through JSON.stringify and come out through JSON.parse.

Making text safe for Mix It Up

// Mix It Up rewrites a dollar sign followed by letters, and a word in curly brackets.
// These characters are swapped for codes that mean the same thing to JSON.
// The less-than sign is swapped too, so nothing in the settings can end the script block early.
function makeSafeForMixItUp(text) {
  return text
    .replace(/</g, '\\u003c')
    .replace(/\$/g, '\\u0024')
    .replace(/\{(?=\w+\})/g, '\\u007b');
}

Before showing a widget, Mix It Up searches its whole code for special identifiers (a $ followed by letters, like $username) and for widget properties (a word in curly brackets, like {Width}), and replaces them. A bowl named "Cash$hop" would otherwise break.

Inside JSON text, \u0024 means the same as a dollar sign and \u007b the same as an opening curly bracket. So these three replacements leave the settings meaning exactly the same while hiding them from Mix It Up. The less-than sign is swapped too, so a name like </script> can't end the settings block early.

The program follows the same rule: none of its code has a dollar sign followed by a letter or a word in curly brackets. (That's why you'll see { bowl } with spaces, which Mix It Up leaves alone.)

4. Shapes: area, capacity and when to break

// =====================================================================================
// 4. SHAPES
// =====================================================================================

// The space inside the outline, treated as a closed shape. Its sign shows which way it was drawn.
function signedArea(outline) {
  let area = 0;
  outline.forEach(([x1, y1], i) => {
    const [x2, y2] = outline[(i + 1) % outline.length];
    area += x1 * y2 - x2 * y1;
  });
  return area / 2;
}

function ballArea(settings) {
  const radius = settings.ballSize / 2;
  return Math.PI * radius * radius;
}

// Roughly how many balls fit, so a reload doesn't rebuild balls that spilled long ago.
function estimateCapacity(bowl, settings) {
  return Math.ceil(1.5 * Math.abs(signedArea(bowl.outline)) / ballArea(settings));
}

// A sensible "Breaks at" number for this outline and ball size.
function suggestedBreakAt(bowl, settings) {
  const area = Math.abs(signedArea(bowl.outline));
  if (area < ballArea(settings)) return Infinity; // No outline yet, so it never fills
  return Math.max(1, Math.round(FILL_FACTOR * area / ballArea(settings)));
}

// How many balls this bowl holds before it breaks. Infinity means it doesn't break by count.
function breakLimit(bowl, settings) {
  if (bowl.breakMode !== 'count') return Infinity;
  return bowl.breakAt || suggestedBreakAt(bowl, settings);
}

// The highest point of the outline: its rim.
function rimHeight(outline) {
  return outline.length ? Math.min(...outline.map(([, y]) => y)) : SIZE;
}
  • signedArea is the "shoelace formula": walk round the outline, add up cross products, halve. The result is the area inside the outline (closed by a straight line across the top). It's positive or negative depending on which way round you drew it, which makeWalls uses.
  • estimateCapacity: the outline's area divided by one ball's area, times 1.5. A generous guess at how many balls fit. On a reload, older balls beyond this are treated as spilled long ago, rather than piled up to the sky.
  • suggestedBreakAt: the "about N" shown in the editor, using FILL_FACTOR. With no outline, it's Infinity ("never").
  • breakLimit: the number this bowl breaks at. It's your Breaks at number if you typed one, otherwise the suggestion. For "when the pile reaches the top" and "never" it's Infinity, because those don't count.
  • rimHeight: the highest point of the outline. Remember, smaller y is higher up.

Walls from the outline

// Builds a thick wall on the outer side of each stretch of the outline. Balls stop exactly on
// the drawn line, and thick walls stop fast balls and heavy piles from pushing through.
function makeWalls(outline) {
  const walls = [];
  const outward = signedArea(outline) < 0 ? 1 : -1;
  for (let i = 1; i < outline.length; i++) {
    const [x1, y1] = outline[i - 1];
    const [x2, y2] = outline[i];
    const length = Math.hypot(x2 - x1, y2 - y1);
    if (!length) continue;
    const alongX = (x2 - x1) / length;
    const alongY = (y2 - y1) / length;
    // Walls overlap at the joints to close the gaps. The two ends stay flush with the line.
    const before = i > 1 ? WALL / 2 : 0;
    const after = i < outline.length - 1 ? WALL / 2 : 0;
    const shift = (after - before) / 2;
    const x = (x1 + x2) / 2 + alongX * shift - outward * alongY * WALL / 2;
    const y = (y1 + y2) / 2 + alongY * shift + outward * alongX * WALL / 2;
    walls.push(Bodies.rectangle(x, y, length + before + after, WALL, {
      isStatic: true,
      angle: Math.atan2(y2 - y1, x2 - x1),
      friction: 1, // Balls touching a wall use the lower friction, so the setting decides.
    }));
  }
  return walls;
}

The heart of the bowl. For each stretch between two outline points it makes one static (never-moving) rectangle, WALL thick:

  • alongX, alongY is the direction of the stretch, one step long. Turned sideways (-alongY, alongX) it points across the line. outward (from signedArea) picks the side that's outside the bowl.
  • The rectangle's middle is pushed half a wall outward, so its inner face lies exactly on your line. Balls rest on the drawn line, not in it.
  • before and after make each wall half a wall longer at joints, so neighbouring walls overlap and no ball slips through a corner. The first and last walls aren't lengthened at the rim, so the bowl's lip stays where you drew it.
  • friction: 1: Matter.js uses the lower friction of the two things touching, so the ball's Friction slider is what decides.

Cutting shapes into shards

function centroid(points) {
  const x = points.reduce((sum, point) => sum + point[0], 0) / points.length;
  const y = points.reduce((sum, point) => sum + point[1], 0) / points.length;
  return [x, y];
}

// Cuts a shape in two along a straight line through a point at an angle.
// Returns both halves and the crack: the two places where the line crosses the shape's edge.
function cutShape(points, [px, py], angle) {
  const normalX = -Math.sin(angle);
  const normalY = Math.cos(angle);
  const side = ([x, y]) => (x - px) * normalX + (y - py) * normalY;
  const left = [];
  const right = [];
  const crack = [];
  points.forEach((point, i) => {
    const next = points[(i + 1) % points.length];
    const a = side(point);
    const b = side(next);
    if (a >= 0) left.push(point);
    if (a <= 0) right.push(point);
    if ((a > 0 && b < 0) || (a < 0 && b > 0)) {
      const t = a / (a - b);
      const crossing = [point[0] + (next[0] - point[0]) * t, point[1] + (next[1] - point[1]) * t];
      left.push(crossing);
      right.push(crossing);
      crack.push(crossing);
    }
  });
  return { left, right, crack };
}

// Cracks a width x height rectangle into a number of pieces along random lines.
// Each time, the biggest piece is cut in two, so the pieces end up roughly even.
function makeShards(width, height, count) {
  let pieces = [[[0, 0], [width, 0], [width, height], [0, height]]];
  const cracks = [];
  const smallest = width * height * 0.02;
  for (let tries = 0; pieces.length < count && tries < count * 20; tries++) {
    pieces.sort((a, b) => Math.abs(signedArea(b)) - Math.abs(signedArea(a)));
    const piece = pieces[0];
    const [cx, cy] = centroid(piece);
    const point = [cx + random(-0.15, 0.15) * width, cy + random(-0.15, 0.15) * height];
    const { left, right, crack } = cutShape(piece, point, random(0, Math.PI));
    if (left.length < 3 || right.length < 3) continue;
    if (Math.abs(signedArea(left)) < smallest || Math.abs(signedArea(right)) < smallest) continue;
    pieces = [left, right, ...pieces.slice(1)];
    if (crack.length === 2) cracks.push(crack);
  }
  return { pieces, cracks };
}
  • centroid: the middle of a shape (the average of its corners).
  • cutShape cuts a shape along a straight line. For each corner, side works out which side of the line it's on (positive or negative). Corners go to the left or right piece. Where an edge crosses the line, the crossing point is worked out (t is how far along the edge) and added to both pieces, and to crack, the line drawn on the picture.
  • makeShards starts with the picture's rectangle. It sorts the pieces so the biggest is first, cuts it through a point near its middle at a random angle, and repeats until there are enough pieces. It skips any cut that would leave a sliver smaller than 2% of the picture, so you never get needle-thin shards. The cuts are random, so every break looks different.

// Crops the ball picture to a circle once, so any picture makes a round ball.
function makeBallSprite(image, size) {
  const sprite = document.createElement('canvas');
  sprite.width = sprite.height = size * 2;
  const painter = sprite.getContext('2d');
  painter.arc(size, size, size, 0, Math.PI * 2);
  painter.clip();
  if (!image) {
    painter.fillStyle = '#ffb02e'; // No picture: a plain orange ball
    painter.fillRect(0, 0, size * 2, size * 2);
    return sprite;
  }
  const scale = size * 2 / Math.min(image.width, image.height);
  const width = image.width * scale;
  const height = image.height * scale;
  painter.drawImage(image, size - width / 2, size - height / 2, width, height);
  return sprite;
}

      painter.fillStyle = settings[key];
      painter.fillRect(0, 0, sprite.width, sprite.height);
    }
    sprites[kind] = sprite;

}

// The bowl picture with crack lines drawn on it. "source-atop" only paints where the picture
// is already visible, so the cracks never show up on its see-through parts.
function makeCrackedPicture(image, width, height, cracks) {
  const canvas = document.createElement('canvas');
  canvas.width = Math.max(1, Math.round(width));
  canvas.height = Math.max(1, Math.round(height));
  const painter = canvas.getContext('2d');
  painter.drawImage(image, 0, 0, width, height);
  painter.globalCompositeOperation = 'source-atop';
  painter.lineCap = 'round';
  for (const [color, lineWidth] of [['rgba(0, 0, 0, 0.7)', 5], ['rgba(255, 255, 255, 0.7)', 2]]) {
    painter.strokeStyle = color;
    painter.lineWidth = lineWidth;
    for (const [[x1, y1], [x2, y2]] of cracks) {

      painter.moveTo(x1, y1);
      painter.lineTo(x2, y2);
      painter.stroke();
    }
  }
  return canvas;
}

  • makeBallSprites makes one ball per kind of event.   • makeCrackedPicture paints the bowl picture, then the crack lines: a dark line, then a thin light line on top, which reads as a crack. source-atop only paints where the picture already has colour, so cracks don't appear on its see-through parts.

// Made by the browser itself, so there are no sound files. In OBS, tick "Control audio via
// OBS" on the source to hear them on stream.

let audio = null;

function playSound(kind, volume) {
  if (!(volume > 0)) return;
  try {
    audio = audio || new AudioContext();
    if (audio.state === 'suspended') audio.resume();
    const now = audio.currentTime;
    const loudness = audio.createGain();
    loudness.connect(audio.destination);
    if (kind === 'crash') {
      // Random crackle that dies away: the sound of something breaking.
      const length = Math.round(audio.sampleRate * 0.8);
      const buffer = audio.createBuffer(1, length, audio.sampleRate);
      const samples = buffer.getChannelData(0);
      for (let i = 0; i < length; i++) samples[i] = random(-1, 1) * Math.pow(1 - i / length, 3);
      const noise = audio.createBufferSource();
      noise.buffer = buffer;
      noise.connect(loudness);
      loudness.gain.value = volume;
      noise.start(now);
    } else {
      // A short tone that slides: up for a new ball ("plip"), down for a shake ("bwomp").
      const tone = audio.createOscillator();
      const start = kind === 'shake' ? 220 : random(500, 900);
      const end = kind === 'shake' ? 70 : start * 2;
      const length = kind === 'shake' ? 0.4 : 0.12;
      tone.frequency.setValueAtTime(start, now);
      tone.frequency.exponentialRampToValueAtTime(end, now + length);
      loudness.gain.setValueAtTime(volume * 0.4, now);
      loudness.gain.exponentialRampToValueAtTime(0.001, now + length);
      tone.connect(loudness);
      tone.start(now);
      tone.stop(now + length);
    }
  } catch {
    // No sound available here. Carry on silently.
  }
}

Sounds made by the browser itself, with the Web Audio system, so the file needs no sound files. audio is the browser's sound "studio", made the first time a sound plays.

  • Crash: a short recording of random noise is made on the spot. Each sample is a random number between -1 and 1, made quieter towards the end (Math.pow(1 - i / length, 3)), which sounds like something shattering.
  • Plip (a new ball) and bwomp (a shake): an oscillator, a pure tone, slides from one pitch to another while its loudness fades to nothing. Each plip starts at a random pitch between 500 and 900, so a flood of balls sounds like rain, not a machine gun. Change those numbers for higher or lower plips.
  • volume comes from the Sound volume slider; 0 plays nothing at all. Everything is inside try, so a PC without sound carries on silently.

In OBS, a browser source only sends its sound to your stream if Control audio via OBS is ticked on it.

// =====================================================================================
// Adds balls to a game's count, remembering each ball's kind (one letter per ball in
// state.kinds) and who sent it (state.names). Both lists line up with the balls still owed.
function owe(state, count, kind, name) {
  count = Math.min(count, MAX_PER_CALL);
  state.balls += count;
  state.kinds += kind.repeat(count);
  for (let i = 0; i < count; i++) state.names.push(name || null);
}

// Makes the kinds and names lists exactly as long as the count, for example after an update.
function lineUp(state) {
  state.kinds = String(state.kinds || '').slice(0, state.balls).padEnd(state.balls, 'x');
  state.names = (Array.isArray(state.names) ? state.names : []).slice(0, state.balls);
  while (state.names.length < state.balls) state.names.push(null);
}

Version 2 remembers, for every ball still waiting or in the bowl, what kind it is and who sent it. Two lists sit next to the count in state:

  • state.kinds: one letter per ball, as text. Twelve balls might be "sssfbbbcxxxx". Text is the smallest way to store this, and it's saved, so colours survive a reload.
  • state.names: a list with a name (or null) per ball, in the same order.

owe is the one place balls are added: it raises the count and adds a letter and a name for each new ball ('s'.repeat(3) is "sss"). lineUp makes both lists exactly as long as the count, cutting or padding with x and null. That's what lets a version 1 save, which has a count but no lists, carry on working.

The rule that keeps everything right: position 0 in the lists is always the first ball of the bowl on screen. A ball's place is simply how many balls have dropped before it, and when a bowl breaks, its balls are cut off the front of both lists.

Setting up a game

async function createGame({ canvas, settings, state, save, onBreak }) {
  const context = canvas.getContext('2d');
  const engine = Engine.create({ enableSleeping: true });
  engine.gravity.y = settings.gravity;

  const radius = settings.ballSize / 2;
  const maxSpeed = 0.75 * (radius + WALL / 2);
  const sprites = makeBallSprites(await loadPicture(settings, 'ball'), settings);

  const balls = new Set(); // Balls in the bowl
  const debris = new Set(); // Balls falling away from a broken bowl
  let shards = []; // Falling pieces of a broken bowl
  let current = null; // The bowl on screen: its settings, picture, walls and limits
  let upcoming = null; // The bowl that comes back after a break, once its picture has loaded
  let phase = 'filling'; // 'filling', 'cracking', 'broken' or 'returning'
  let phaseStart = 0; // The step the phase began on
  let steps = 0; // Steps since the game started
  let dropped = 0; // Balls dropped into this bowl so far
  let lastDrop = 0; // The step the last ball was dropped on
  let restingAtTop = 0; // Steps in a row a ball has rested at the rim
  let stillFor = 0; // Steps in a row every ball in the bowl has been (almost) still
  let shakeUntil = 0; // The bowl picture wobbles until this step
  let confetti = [];
  let stopped = false;

createGame builds one running bowl and gives back a few controls. The overlay calls it once with the real count. The editor's test view calls it with a pretend count. It gets:

  • canvas: where to draw. settings: the bowls and physics settings.
  • state: the numbers it keeps up to date: balls (how many balls belong to the bowl on screen, including ones still waiting to drop), bowlId (which bowl is showing) and breaks. save is called whenever they change; the test view passes one that does nothing.
  • onBreak: what to do when a bowl breaks (the overlay tells Mix It Up).

Inside, Engine.create({ enableSleeping: true }) makes the physics world. "Sleeping" lets balls that have stopped moving rest without being recalculated, which saves effort with big piles. maxSpeed is the speed limit that stops balls jumping through walls: three quarters of the distance from a ball's middle to the far side of a wall, per step.

The let lines are the game's memory. phase is the most important: the bowl is always filling, cracking, broken or returning, and steps counts physics steps so each phase knows how long it has lasted.

Getting a bowl ready

  function findBowl(id) {
    return settings.bowls.find((bowl) => bowl.id === id) || settings.bowls[0];
  }

  }

    current.walls = makeWalls(next.bowl.outline);
    Composite.add(engine.world, current.walls);
    dropped = 0;
    restingAtTop = 0;
    stillFor = 0;
  }

    phase = next;
    phaseStart = steps;
  }

  // How many balls should end up in this bowl: everything owed, up to the break limit.

  • findBowl: the bowl with this id, or the first one if it's gone (for example, deleted in the editor).
  • prepareBowl loads the bowl's picture and works out its height (keeping the picture's shape), its break limit, capacity and rim. It's async because loading a picture takes a moment. That's why the next bowl starts loading the moment the old one cracks.
  • putOnStage makes the walls, adds them to the world and starts the count for this bowl at zero.
  • wanted(): how many balls this bowl should get, which is everything owed, but never more than its break limit. Balls beyond the limit wait for the next bowl.

Dropping a ball

  // live is false while rebuilding the pile after a reload: no sound, no name.
  function dropBall(live) {
    const { bowl } = current;
    // Always a little scatter, so balls don't land balanced on top of each other.
    const scatter = bowl.dropWidth + radius;
    const x = bowl.dropX + (Math.random() - 0.5) * scatter;
    const ball = Bodies.circle(x, bowl.dropY, radius, {
      restitution: settings.bounciness,
      friction: settings.friction,
      frictionStatic: 0,
    });
    // The kinds and names lists line up with the balls owed to this bowl, so this ball's
    // place in them is the number of balls dropped so far.
    ball.kind = state.kinds[dropped] || 'x';
    if (live && settings.showNames && state.names[dropped]) {
      ball.sender = state.names[dropped]; // Not "label": Matter.js already uses that name
      ball.senderUntil = steps + NAME_TIME;
    }
    if (live) playSound('drop', settings.volume);
    balls.add(ball);
    Composite.add(engine.world, ball);
    dropped++;
    lastDrop = steps;
  }

A ball appears at the drop point, moved left or right by a random amount up to half the Drop width. Even with a drop width of 0 there's a little scatter (+ radius), so balls never balance perfectly on top of each other.

  • restitution = Bounciness. Raise it and balls bounce higher; 0 means they don't bounce at all.
  • friction = Friction. Raise it and balls stop rolling sooner; 0 makes them slide like ice.
  • frictionStatic: 0 stops balls sticking to slopes when they're still.

The ball then looks up its place in the lists (dropped, the number dropped before it) to learn its kind, and its sender if names are on. live is false while the pile is rebuilt after a reload: those balls get their colour back, but no name and no sound, because nobody needs to hear 150 plips at once.

One step of physics

  // One step of physics. Fast balls are slowed, and balls that leave the stage are removed.
  function physicsStep() {
    Engine.update(engine, TICK);
    for (const group of [balls, debris]) {
      for (const ball of group) {
        // Capped so a fast ball can't jump straight through a wall.
        if (ball.speed > maxSpeed) Body.setSpeed(ball, maxSpeed);
        if (ball.position.y > SIZE + settings.ballSize) {
          group.delete(ball);
          Composite.remove(engine.world, ball);
        }
      }
    }
  }

  // Shards aren't part of the physics world. They just fly and spin under gravity.
  function moveShards() {
    for (const shard of shards) {
      shard.vy += 0.28 * settings.gravity; // About as fast as Matter.js makes balls fall
      shard.x += shard.vx;
      shard.y += shard.vy;
      shard.angle += shard.spin;
    }
    shards = shards.filter((shard) => shard.y - shard.reach < SIZE);
    for (const piece of confetti) {
      piece.vy += 0.3 * settings.gravity;
      piece.vx *= 0.98; // Air slows them down sideways
      piece.x += piece.vx;
      piece.y += piece.vy;
      piece.angle += piece.spin;
    }
    confetti = confetti.filter((piece) => piece.y < SIZE + 20);
  }

Moves the world forward one sixtieth of a second (Engine.update(engine, TICK)). Then, for every ball: if it's faster than the speed limit, slow it down to the limit; if it has fallen below the bottom of the stage, remove it for good.

moveShards moves the pieces of a broken bowl, and the confetti, which falls a little slower and loses 2% of its sideways speed each step (vx *= 0.98) so it drifts like paper. They aren't in the physics world, because they don't need to hit anything. Each step their downward speed grows by 0.28 × gravity (about how fast Matter.js makes balls fall), and they move and spin. Pieces below the stage are dropped.

Is the bowl full?

  // Does this bowl count as full yet?
  function checkFull() {
    const mode = current.bowl.breakMode;
    if (mode === 'count') {
      if (dropped < current.limit) return;
      // Waits for the last balls to land and the pile to settle, so none are left in mid-air.
      let allStill = true;
      for (const ball of balls) if (ball.speed > 0.5) allStill = false;
      stillFor = allStill ? stillFor + 1 : 0;
      if (stillFor >= FULL_PAUSE || steps - lastDrop >= FULL_WAIT_MAX) breakNow();
    } else if (mode === 'auto') {
      // A ball that has stopped moving with its top at or above the rim means the pile is full.
      // Balls still near the drop point are skipped, because a new ball starts out still.
      let atTop = false;
      for (const ball of balls) {
        const still = ball.speed < 0.3;
        const belowDrop = ball.position.y > current.bowl.dropY + radius * 2;
        if (still && belowDrop && ball.position.y - radius <= current.rimY + 2) atTop = true;
      }
      restingAtTop = atTop ? restingAtTop + 1 : 0;
      if (restingAtTop >= RESTING_AT_TOP) breakNow();
    }
  }

Runs every step while filling. Three modes, set per bowl in the editor:

  • At a number of balls ('count'): once the bowl has had all its balls, wait until every ball has been almost still (speed < 0.5) for FULL_PAUSE steps in a row, so nothing is left hanging in mid-air when it cracks. If balls keep wobbling, it breaks anyway after FULL_WAIT_MAX steps.
  • When the pile reaches the top ('auto'): if some ball has stopped moving with its top at or above the rim for RESTING_AT_TOP steps in a row, the bowl is full. Balls near the drop point are ignored, because a brand-new ball is still for a moment too.
  • Never ('off'): nothing to check.

The heartbeat

  function update() {
    if (stopped) return;
    steps++;
    physicsStep();
    moveShards();
    const age = steps - phaseStart;
    if (phase === 'filling') checkFull();
    else if (phase === 'cracking' && age >= CRACK_TIME) shatter();
    else if (phase === 'broken' && upcoming && age >= settings.returnSeconds * 60) comeBack();
    else if (phase === 'returning' && age >= FADE_TIME) setPhase('filling');
  }

update runs 60 times a second. It counts the step, moves the physics and the shards, then asks "has the current phase finished?":

  • filling: is the bowl full? (checkFull)
  • cracking: has CRACK_TIME passed? Then shatter.
  • broken: has the next bowl's picture loaded, and have Comes back after seconds passed? Then bring it in.
  • returning: has FADE_TIME passed? Then it's filling again.

This pattern, one variable that's always exactly one of a few phases plus rules for moving between them, is called a state machine. It keeps the break sequence easy to follow and change.

Breaking, part 1: the count and the cracks

  // Step 1 of a break: work out the count, draw cracks and shake. Returns false if it can't break now.
  function breakNow() {
    if (phase !== 'filling' && phase !== 'returning') return false;
    const used = dropped;
    // Balls above the limit, and balls still waiting to drop, carry over to the next bowl.
    state.balls = Math.max(0, state.balls - used);
    state.kinds = state.kinds.slice(used);
    state.names = state.names.slice(used);
    state.breaks = (state.breaks || 0) + 1;
    const nextBowl = pickNextBowl(settings, current.bowl.id);
    state.bowlId = nextBowl.id; // Saved now, so a reload during the break shows the next bowl
    save();

    upcoming = null;
    prepareBowl(nextBowl).then((next) => {
      upcoming = next;
    });

    const { pieces, cracks } = makeShards(current.bowl.width, current.height, settings.shards);
    current.pieces = pieces;
    current.cracked = current.picture
      ? makeCrackedPicture(current.picture, current.bowl.width, current.height, cracks)
      : null;
    setPhase('cracking');
    onBreak({ bowlName: current.bowl.name, balls: used, breaks: state.breaks, nextBowlName: nextBowl.name });
    return true;
  }

Only a filling (or fading-in) bowl can break. First the numbers, saved straight away so a refresh mid-break can't lose anything:

  • The balls dropped into this bowl are used up: state.balls goes down by that many. Whatever is left (balls over the limit, and balls that arrived but hadn't dropped yet) carries over to the next bowl.
  • The same number of letters and names are cut off the front of state.kinds and state.names (slice(used)), so the lists stay lined up with the carried-over balls.
  • state.bowlId becomes the next bowl now, so a refresh during the break shows the new bowl.

Then the next bowl's picture starts loading, the shards and crack lines are worked out, the cracked picture is painted, the phase becomes cracking, and onBreak is told: which bowl, how many balls, how many breaks, and which bowl comes next.

Breaking, part 2: everything falls

  // Step 2: the walls vanish, the pieces fly apart and every ball falls.
  function shatter() {
    Composite.remove(engine.world, current.walls);
    for (const ball of balls) {
      ball.collisionFilter = { group: 0, category: DEBRIS.category, mask: DEBRIS.mask };
      Sleeping.set(ball, false); // A resting ball is "asleep" and wouldn't fall otherwise
      Body.setVelocity(ball, { x: ball.velocity.x + random(-1.5, 1.5), y: ball.velocity.y - random(0, 2) });
      debris.add(ball);
    }
    balls.clear();

    const { bowl } = current;
    shards = current.cracked ? current.pieces.map((points) => {
      const [cx, cy] = centroid(points);
      const shape = points.map(([x, y]) => [x - cx, y - cy]); // Corners, measured from the middle
      return {
        shape,
        reach: Math.max(...shape.map(([x, y]) => Math.hypot(x, y))),
        picture: current.cracked,
        offsetX: -cx,
        offsetY: -cy,
        x: bowl.x + cx,
        y: bowl.y + cy,
        angle: 0,
        vx: (cx - bowl.width / 2) * 0.012 + random(-1, 1), // Pieces fly outwards from the middle
        vy: random(-3, -0.5), // and jump up a little first
        spin: random(-0.05, 0.05),
      };
    }) : [];

    playSound('crash', settings.volume);
    if (settings.confetti) {
      for (let i = 0; i < CONFETTI_PIECES; i++) {
        confetti.push({
          x: bowl.x + bowl.width / 2,
          y: bowl.y + current.height / 3,
          vx: random(-9, 9),
          vy: random(-16, -5),
          size: random(6, 12),
          color: 'hsl(' + Math.round(random(0, 360)) + ', 90%, 60%)',
          angle: random(0, Math.PI),
          spin: random(-0.3, 0.3),
        });
      }
    }
    setPhase('broken');
  }
  • The walls are removed, so nothing holds the balls up.
  • Each ball is moved to the DEBRIS category (so it won't land in the next bowl), woken up (Sleeping.set(ball, false), or a resting ball would float in mid-air), and nudged sideways and up a little. Then it moves from balls to debris.
  • The crash plays, and if Confetti is on, 150 coloured pieces start at the bowl's middle, flying outwards and upwards at random. hsl(…, 90%, 60%) is a colour picked by its position round the colour wheel (0 to 360), so every piece is a bright, random colour.
  • Each piece becomes a shard: its corners measured from its own middle (so it can spin around its middle), where it is on the stage, and a random push. vx pushes pieces away from the bowl's centre (raise 0.012 for a more violent explosion), vy makes them hop up first, spin sets how fast they turn.

Shaking the bowl

  // Throws every ball in the bowl up into the air. Some may fly out!
  function shake(strength) {
    if (phase !== 'filling' && phase !== 'returning') return;
    shakeUntil = steps + SHAKE_TIME;
    for (const ball of balls) {
      Sleeping.set(ball, false);
      Body.setVelocity(ball, { x: random(-2, 2) * strength, y: -random(3, 7) * strength });
    }
    playSound('shake', settings.volume);
  }

shake throws every ball in the bowl up and a little sideways: -random(3, 7) * strength upwards (negative y is up). Sleeping balls are woken first, or they'd ignore it. The bowl picture wobbles for SHAKE_TIME steps (see draw), and the bwomp plays. The walls don't move, so a strong shake can fling balls over the rim and off the stage. They still counted as dropped, just like balls that spill. A bowl that's cracking or broken can't be shaken.

Breaking, part 3, and emptying

  // Step 3: the next bowl fades in and the waiting balls start dropping again.
  function comeBack() {
    putOnStage(upcoming);
    upcoming = null;
    setPhase('returning');
  }

  function empty() {
    Composite.remove(engine.world, [...balls, ...debris]);
    balls.clear();
    debris.clear();
    dropped = 0;
    restingAtTop = 0;
    state.balls = 0;
    state.kinds = '';
    state.names = [];
    save();
  }

  // Rebuilds the pile out of sight after the page loads.
  function refill() {
    const target = wanted();
    dropped = Math.max(0, target - current.capacity); // These would have spilled long ago
    while (dropped < target) {
      dropBall(false);
      for (let i = 0; i < 6; i++) physicsStep();
    }
    for (let i = 0; i < 180; i++) physicsStep();
    lastDrop = steps;
  }
  • comeBack puts the prepared bowl on stage and starts it fading in. Waiting balls start dropping straight away, during the fade.
  • empty removes every ball (in the bowl and falling), sets the count to 0 and clears the kinds and names. A break in progress still finishes, with an empty bowl coming back.
  • refill runs when the page opens: it rebuilds the pile out of sight by dropping a ball, running 6 physics steps, and repeating, then 180 more steps to let it settle. All of that happens before the first frame is drawn, so viewers never see it. Balls beyond the capacity estimate are counted as long gone instead of rebuilt.

Drawing

  function drawBall(ball) {
    context.save();
    context.translate(ball.position.x, ball.position.y);
    context.rotate(ball.angle);
    context.drawImage(sprites[ball.kind] || sprites.x, -radius, -radius, settings.ballSize, settings.ballSize);
    context.restore();
  }

  // White text with a dark edge, readable over anything.
  function drawText(text, x, y, size) {
    context.font = 'bold ' + size + 'px system-ui, "Segoe UI", sans-serif';
    context.textAlign = 'center';
    context.lineWidth = size / 5;
    context.strokeStyle = 'rgba(0, 0, 0, 0.8)';
    context.strokeText(text, x, y);
    context.fillStyle = '#fff';
    context.fillText(text, x, y);
  }

  function drawSender(ball) {
    if (!ball.sender || steps > ball.senderUntil) return;
    context.globalAlpha = Math.min(1, (ball.senderUntil - steps) / 30); // Fades out at the end
    drawText(ball.sender, ball.position.x, ball.position.y - radius - 6, 16);
    context.globalAlpha = 1;
  }

  function draw() {
    if (stopped) return;
    context.clearRect(0, 0, SIZE, SIZE);
    if (current && current.picture && phase !== 'broken') {
      const { bowl } = current;
      let picture = current.picture;
      let shakeX = 0;
      let shakeY = 0;
      if (phase === 'cracking') {
        picture = current.cracked || picture;
        const shake = 4 * (steps - phaseStart) / CRACK_TIME; // The shaking grows
        shakeX = random(-shake, shake);
        shakeY = random(-shake, shake);
      } else if (steps < shakeUntil) {
        shakeX = random(-6, 6);
        shakeY = random(-6, 6);
      }
      context.globalAlpha = phase === 'returning' ? Math.min(1, (steps - phaseStart) / FADE_TIME) : 1;
      context.drawImage(picture, bowl.x + shakeX, bowl.y + shakeY, bowl.width, current.height);
      context.globalAlpha = 1;
    }
    for (const shard of shards) {
      context.save();
      context.translate(shard.x, shard.y);
      context.rotate(shard.angle);
      context.beginPath();
      shard.shape.forEach(([x, y], i) => (i ? context.lineTo(x, y) : context.moveTo(x, y)));
      context.closePath();
      context.clip();
      context.drawImage(shard.picture, shard.offsetX, shard.offsetY);
      context.restore();
    }
    balls.forEach(drawBall);
    debris.forEach(drawBall);
    balls.forEach(drawSender);
    for (const piece of confetti) {
      context.save();
      context.translate(piece.x, piece.y);
      context.rotate(piece.angle);
      context.fillStyle = piece.color;
      context.fillRect(-piece.size / 2, -piece.size / 4, piece.size, piece.size / 2);
      context.restore();
    }
    if (settings.showCounter && current && phase !== 'broken') {
      const count = Number.isFinite(current.limit) ? dropped + ' / ' + current.limit : String(dropped);
      drawText(count, current.bowl.x + current.bowl.width / 2, current.rimY - 24, 36);
    }
    requestAnimationFrame(draw);
  }

draw runs before every screen refresh (requestAnimationFrame). It clears the canvas and paints, back to front:

  1. The bowl. While cracking, the cracked picture is drawn shifted by a random amount that grows each step, which is the shake (raise the 4 to shake harder). While returning, globalAlpha fades it from see-through to solid. While broken, it isn't drawn.
  2. The shards. Each one moves the pen to the shard, turns it, cuts a shard-shaped hole to paint through (clip), and paints the cracked picture so the right part shows through.
  3. The balls, in the bowl and falling, each turned the way it has rolled, using the sprite for its kind (sprites[ball.kind]).
  4. Names above the newest balls (drawSender). It's called sender, not label, because Matter.js already gives every body a label ("Circle Body"), which is exactly what showed up when it was called that. Each name fades out over its last half second.
  5. The confetti: small rectangles, each turned to its own angle.
  6. The counter, if it's on: balls dropped into this bowl, and its limit if it breaks at a number.

drawText writes white text with a dark edge (strokeText then fillText), which stays readable over any game.

While the bowl is being shaken (steps < shakeUntil), the picture is drawn a few dots off in a random direction each frame: the wobble.

Starting the game

  // ---- Start ----
  putOnStage(await prepareBowl(findBowl(state.bowlId)));
  refill();

  const dropTimer = setInterval(() => {

Put the right bowl on stage, rebuild the pile, then start three loops: dropTimer drops a waiting ball every DROP_EVERY milliseconds (only while the bowl is there), stepTimer runs update 60 times a second, and draw keeps painting.

The game hands back its controls: breakNow, empty, shake, stop (used when the test view closes) and two for checking from the console. Type realGame.info() in the overlay's console to see the phase, how many balls are in the bowl and its limit.

Which bowl comes back

// After a break: the same bowl again, or the next one in the list.
function pickNextBowl(settings, currentId) {
  const list = settings.bowls;
  const index = list.findIndex((bowl) => bowl.id === currentId);
  if (!settings.cycleBowls) return list[index] || list[0];
  return list[(index + 1) % list.length];
}

With "The next bowl in the list comes back" off, it's the same bowl again. With it on, it's the next one, and % list.length wraps from the last bowl back to the first.

Understanding what Mix It Up sends

// Mix It Up sends one object of named texts, such as { count: "5" }.
// Typed in the console it might be a plain 5. This accepts both and picks out the value.
// With firstIfMissing false, a missing name gives '' instead of the first value.
function pickValue(input, names, firstIfMissing = true) {
  if (input === null || input === undefined) return '';
  if (typeof input !== 'object') return firstIfMissing ? input : '';
  const keys = Object.keys(input);
  for (const name of names) {
    const key = keys.find((k) => k.trim().toLowerCase() === name);
    if (key !== undefined) return input[key];
  }
  return keys.length && firstIfMissing ? input[keys[0]] : '';
}

// The optional "user" a ball came from, tidied up, or '' if none was sent.
function pickUser(input) {
  return String(pickValue(input, ['user', 'username', 'name'], false) || '').trim().replace(/^@/, '').slice(0, 25);
}

// "25", " 1,000 ", 25 and 25.7 all work. Anything else, like an identifier Mix It Up
// didn't fill in, gives NaN ("not a number") and is ignored.
function toWholeNumber(value) {
  const text = String(value).trim().replace(/[,\s]/g, '');
  if (!/^\d+(\.\d+)?$/.test(text)) return NaN;
  return Math.floor(Number(text));
}

Mix It Up's Run Widget Function calls a function with one object of named texts. A parameter named count with value 5 arrives as { count: "5" }. (This comes from Mix It Up's source code: it calls contentWindow[functionName](parameters).) In the console you'd more naturally type addBalls(5). pickValue accepts both: for an object it looks for a sensible name (count, amount…, in any capitals), or takes the first value; anything else is used as it is.

firstIfMissing is for optional parameters. With it off, a missing name gives nothing rather than "the first value", so { count: "5" } isn't mistaken for a user called 5. pickUser uses that to read the optional user parameter, removing a leading @ and keeping at most 25 letters so a silly name can't cover the screen.

toWholeNumber accepts 5, "5", " 1,000 " and "25.7" (rounded down). Anything else gives NaN, "not a number". The usual case is a special identifier Mix It Up didn't recognise, arriving as the literal text $bitsamount. !(count > 0) is true for NaN, zero and negatives, so all of those are ignored with a note in the console instead of breaking anything.

The functions Mix It Up calls

// The one place balls are added to the real bowl.
function addKind(count, kind, name) {
  owe(realState, count, kind, name);
  saveState();
  note('+' + count + (name ? ' from ' + name : '') + ' (total ' + realState.balls + ')');
  return realState.balls;
}

// Parameters: count (required), and optionally user (who sent it) and kind
// (follow, sub, bits or chat, for the ball's colour).
function addBalls(input) {
  const count = toWholeNumber(pickValue(input, ['count', 'balls', 'amount', 'number']));
  if (!(count > 0)) {
    note('addBalls ignored, because this is not a number of balls: ' + JSON.stringify(input));
    return realState.balls;
  }
  const kindWord = String(pickValue(input, ['kind', 'type', 'event'], false)).trim().toLowerCase();
  return addKind(count, KIND_LETTERS[kindWord] || 'x', pickUser(input));
}

function addFollower(input) {
  const shown = String(pickValue(input, ['username', 'user', 'name', 'follower'])).trim().replace(/^@/, '');
  const name = shown.toLowerCase(); // Compared in small letters, so "Sam" and "sam" are the same person
  if (!name) {
    note('addFollower ignored, because no username came with it: ' + JSON.stringify(input));
    return realState.balls;
  }
  // Someone who unfollows and follows again only counts once.
  if (followers.has(name)) {
    note(name + ' followed before, so no ball this time');
    return realState.balls;
  }
  followers.add(name);
  return addKind(1, 'f', shown);
}

function addBits(input) {
  const bits = toWholeNumber(pickValue(input, ['amount', 'bits', 'bitsamount']));
  if (!(bits > 0)) {
    note('addBits ignored, because this is not a number of bits: ' + JSON.stringify(input));
    return realState.balls;
  }
  const bitsPerBall = activeSettings ? activeSettings.bitsPerBall : SHARED_DEFAULTS.bitsPerBall;
  return addKind(Math.max(1, Math.floor(bits / bitsPerBall)), 'b', pickUser(input));
}

  realState.balls = 0;
  lineUp(realState);

}

function breakBowl() {

  else breakWaiting = true;

// Bounces the pile. Optional parameter: strength, from 0.5 (a nudge) to 3 (chaos). 1.5 if not given.
function shakeBowl(input) {
  const strength = Number(String(pickValue(input, ['strength', 'power'])).trim());
  if (realGame) realGame.shake(strength >= 0.5 && strength <= 3 ? strength : 1.5);
}
  • addKind is the one place real balls are added: owe, save, and a note in the console.
  • addBalls(count) adds that many balls. Two optional parameters: kind (follow, sub, bits or chat, looked up in KIND_LETTERS) picks the colour, and user is the name shown. The game notices by itself: its drop loop compares dropped with state.balls every 150 ms.
  • addFollower(username) tidies the name (spaces, a leading @, capitals) and adds a ball only if it isn't in followers yet. The list is saved, so someone who unfollows and follows again a month later still doesn't count twice.
  • addBits(amount): one ball per Bits for one ball, rounded down, at least 1. So 250 bits at 100 per ball gives 2, and 40 bits gives 1.
  • emptyBowl() and breakBowl() pass the request on to the game.
  • shakeBowl() shakes the pile. An optional strength between 0.5 and 3 sets how hard; anything else (or nothing) means 1.5. Hook it to a channel point reward and let viewers bounce your bowl.

They're written as function name() {} at the top level, which makes them reachable as window.addBalls, which is exactly where Mix It Up looks.

Telling Mix It Up the bowl broke

// Tells Mix It Up the bowl broke, by running a command through its Developer API.
function tellMixItUp(settings, info) {
  const id = settings.breakCommandId.trim();
  if (!id) return;
  fetch(MIX_IT_UP_API + '/' + encodeURIComponent(id), {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      Arguments: info.bowlName,
      SpecialIdentifiers: {
        bowlname: info.bowlName,
        bowlballs: String(info.balls),
        bowlbreaks: String(info.breaks),
        nextbowlname: info.nextBowlName,
      },
    }),
  })
    .then((response) => note(response.ok ? 'Told Mix It Up the bowl broke' : 'Mix It Up answered ' + response.status))
    .catch(() => note("Couldn't reach Mix It Up's Developer API to say the bowl broke"));
}

Mix It Up's Developer API (Services → Developer API) lets programs on your PC run commands by sending a request to http://localhost:8911/api/v2/commands/ plus the command's ID. fetch sends it, with the bowl's details as special identifiers: bowlname, bowlballs, bowlbreaks and nextbowlname, which become $bowlname and so on in that command. Mix It Up's API allows requests from web pages, which is what makes this possible. If no ID is set, or Mix It Up doesn't answer, nothing happens apart from a note in the console.

  if (realState.liveSeen !== settings.liveBowlId || !settings.bowls.some((bowl) => bowl.id === realState.bowlId)) {

    realState.liveSeen = settings.liveBowlId;

  saveState();

  realGame = await createGame({
    canvas: byId('stage'),
    settings,
    state: realState,
    save: saveState,
    onBreak: (info) => {

    },
  });

What happens in OBS or Mix It Up:

  1. Read the settings written in the file. The overlay never uses settings saved in the browser: OBS's browser is a different browser from the Chrome you edit in, so the file is the only way settings travel.
  2. If this copy carries a new "empty" token (made by Empty the real bowl), set the count to 0, and remember the token so it only happens once.
  3. If you chose a different live bowl in the editor since this overlay last ran, start on it. Otherwise carry on with whichever bowl was showing (it may have changed by breaking).
  4. Start the game with the real count, and on each break, tell Mix It Up.

function remember() {
  history.push(JSON.stringify(currentBowl().outline));

// Where a new point belongs: the stretch of line it adds the least length to.
function nearestStretch(point) {
  const { outline } = currentBowl();
  const detour = (i) => distance(outline[i], point) + distance(point, outline[i + 1]) - distance(outline[i], outline[i + 1]);
  let best = 0;
  for (let i = 1; i < outline.length - 1; i++) if (detour(i) < detour(best)) best = i;
  return best;
}

function startDrag(event) {
  if (event.button !== 0) return;
  event.preventDefault();
  const point = toStage(event);
  const bowl = currentBowl();
  const { outline } = bowl;
  const { target } = event;

  if (target.closest('#drop')) {
    drag = ([x, y]) => {
      bowl.dropX = x;
      bowl.dropY = y;
    };
  } else if (mode === 'move') {
    const offsetX = point[0] - bowl.x;
    const offsetY = point[1] - bowl.y;
    drag = ([x, y]) => {
      bowl.x = x - offsetX;
      bowl.y = y - offsetY;
    };
  } else if (target.dataset.index !== undefined) {
    remember();
    const index = Number(target.dataset.index);
    drag = (position) => {
      outline[index] = position;
    };
  } else if (target === byId('outline')) {
    remember();
    const index = nearestStretch(point) + 1;
    outline.splice(index, 0, point);
    drag = (position) => {
      outline[index] = position;
    };
  } else {
    remember();
    outline.push(point);
    drag = (position) => {
      if (distance(outline.at(-1), position) >= MIN_STEP) outline.push(position);
    };
  }
  render();
}

function removePoint(event) {
  event.preventDefault();
  if (event.target.dataset.index === undefined || mode !== 'draw') return;
  remember();
  currentBowl().outline.splice(Number(event.target.dataset.index), 1);
  render();
  saveSoon();
}

function setMode(next) {
  mode = next;
  byId('editor-stage').classList.toggle('moving', mode === 'move');
  byId('draw-mode').classList.toggle('active', mode === 'draw');
  byId('move-mode').classList.toggle('active', mode === 'move');

}

startDrag runs when the mouse button goes down on the stage, and decides what you're grabbing. The answer becomes drag, a small function that the pointermove handler calls with each new mouse position:

  • On the drop marker: move the drop point.
  • In Move picture mode: move the picture, keeping the spot you grabbed under the mouse.
  • On a point: move that point.
  • On the line: add a point there (nearestStretch finds the stretch that the new point lengthens least) and drag it.
  • On empty space: add a point at the end, then, while the button is held, add another each time the mouse moves MIN_STEP (16) dots. That's freehand drawing. Lower MIN_STEP for smoother but heavier outlines.

remember saves the outline before each change, for Undo. removePoint handles right-click. setMode switches between drawing and moving, and updates the buttons and hint.

async function pictureToText(file, maxSide) {

  const scale = Math.min(1, maxSide / Math.max(picture.width, picture.height));

  const png = canvas.toDataURL('image/png');

  return webp.startsWith('data:image/webp') && webp.length < png.length ? webp : png;
}

    text = await pictureToText(file, kind === 'ball' ? MAX_BALL_PICTURE : MAX_PICTURE);
  } catch {

pictureToText draws the chosen file onto a canvas, shrunk so its longest side is at most 1600 pixels (400 for the ball), then turns it into a data URL. A new bowl picture gets a new name in pictures, so a duplicated bowl keeps its own picture.

//   Type 999 = Custom widget, DisplayOption 1 = Single Widget URL.
function buildWidgetFile(settings) {
  const blank = '00000000-0000-0000-0000-000000000000';
  const widget = {
    Name: 'Twitch Bowl',
    Item: {
      ID: crypto.randomUUID ? crypto.randomUUID() : blank, // Mix It Up gives it a new ID on import anyway
      HTML: buildFile(settings),
      CSS: '',
      Javascript: '',
      Version: 0,
      OverlayEndpointID: blank,
      Type: 999,
      DisplayOption: 1,
      Width: 800,
      Height: 800,
      PositionType: 0,
      XPosition: 0,
      YPosition: 0,
      XMaximum: 0,
      YMaximum: 0,
      Layer: 0,
      // The widget's event boxes. These four feed Follow, Subscription..., TwitchBits and
      // ChatMessageReceived above.
      Follows: true,
      TwitchSubscriptions: true,
      TwitchBits: true,
      ChatMessages: true,
      Chatters: false,
      Raids: false,
      TwitchPowerUps: false,
      Donations: false,
    },
    IsEnabled: true,
    RefreshTime: 0,
  };
  // Mix It Up needs to know which of its types each part is. Its files mark that with a
  // "type" key that starts with a dollar sign, added here so this file never contains one.
  const typeKey = String.fromCharCode(36) + 'type';
  const json = JSON.stringify(widget, null, 2)
    .replace('{\n  "Name"', '{\n  "' + typeKey + '": "MixItUp.Base.Model.Overlay.Widgets.OverlayWidgetV3Model, MixItUp.Base",\n  "Name"')
    .replace('"Item": {\n', '"Item": {\n    "' + typeKey + '": "MixItUp.Base.Model.Overlay.OverlayCustomV3Model, MixItUp.Base",\n');
  return json;
}

function updateResetHint() {
  const armed = activeSettings.emptyArmed;
  byId('reset-hint').textContent = armed
    ? 'The next copy you make (widget, copy or saved file) empties the real bowl once, when Mix It Up loads it.'

A .miuoverlay file is how Mix It Up exports and imports widgets: JSON text describing one widget. The names and numbers come from Mix It Up's source code (OverlayWidgetV3Model and OverlayCustomV3Model):

  • Type: 999 means a Custom widget, and DisplayOption: 1 means "Single Widget URL" (its own link for OBS).
  • HTML is this whole file with your settings, built by buildFile. CSS and Javascript are empty.
  • Follows, TwitchSubscriptions, TwitchBits and ChatMessages tick the widget's event boxes, which is what makes it work with no event commands.
  • Mix It Up needs a $type line at the start of each part, naming its type. This file isn't allowed to contain a dollar sign followed by letters, so it builds the word from String.fromCharCode(36) (character 36 is the dollar sign) and slips the two lines in.

function chooseMode() {
  const hash = location.hash.toLowerCase();

    inFrame = true;

  1. #overlay in the address always means overlay. #edit always means editor.

Part 4. Changing things

Edit bowl.html in a text editor (not the Bowl Editor). After saving, double-click it to check the editor still opens, then press Copy for Mix It Up or Download Mix It Up widget and update the widget (MIXITUP_SETUP.md, "Changing the bowl later"). Keep a copy of the working file first.

Change how many balls an event gives

The simplest way is in Mix It Up, with no code: use the event commands in MIXITUP_SETUP.md Step 2B and change the count value (for example 5 for subs). To do it in code for the widget events, change the number in the function in section 7. For 3 balls per sub:

function Subscription(data) {
  addKind(3, 's', nameOf(data && data.User)); // 3 sub-coloured balls, labelled with the subscriber
}

For bits, change Bits for one ball in the editor. To give 1 ball per 100 bits with no minimum, change Math.max(1, Math.floor(bits / bitsPerBall)) in addBits to Math.floor(bits / bitsPerBall).

Add a new event type

Example: raids add one ball per 10 raiders. Mix It Up's Custom widget has a Raids box, and calls Raid(data) with data.Amount viewers. Add this next to the other widget events in section 7:

function Raid(data) {
  const viewers = toWholeNumber((data && data.Amount) || 0);
  if (viewers > 0) addBalls(Math.max(1, Math.floor(viewers / 10)));
}

Then add Raid to the MIX_IT_UP_FUNCTIONS list just below, and tick Raids on the widget in Mix It Up. Or skip the code completely: make a Twitch Channel Raided event command with Run Widget Function → addBalls, count = $raidviewercount.

The widget event names Mix It Up uses, from its source code: Follow, Raid, Subscription, SubscriptionGifted, MassSubscriptionGifted, TwitchBits, Donation, ChatMessageReceived, ChatMessageDeleted, ChatCleared, UserBanned, UserTimeout, YouTubeSuperChat. Remember the rule: no dollar sign followed by letters, and no word in curly brackets, anywhere in the file.

Change the break animation

  • Slower, more dramatic cracking: raise CRACK_TIME (section 1), for example to 60 for a second of shaking.
  • More violent explosion: in shatter, raise 0.012 (sideways push) and widen random(-3, -0.5) (the hop upwards), for example to random(-8, -2).
  • Harder shaking: in draw, raise the 4 in const shake = 4 * ….
  • Thicker or coloured cracks: in makeCrackedPicture, change the two [colour, width] pairs, for example ['rgba(255, 60, 60, 0.9)', 6] for red cracks.
  • Longer fade-in: raise FADE_TIME.
  • Number of pieces and time until it comes back: these are sliders in the editor (Shards, Comes back after).

Change the fun extras

  • Colours: use the four colour pickers under Fun. To colour another kind of ball, say raids: add r: 'raidColor' to KIND_COLORS and raidColor: '#ff7043', to SHARED_DEFAULTS, then in your Raid function use addKind(count, 'r', nameOf(data.User)).
  • Names show longer: raise NAME_TIME (60 = one second). Bigger names: change 16 in drawSender.
  • Sounds: in playSound, random(500, 900) is the plip's pitch range (lower numbers, deeper plips), and 0.12 its length in seconds. For the crash, change 0.8 (length) or the 3 in Math.pow (higher dies away faster).
  • More confetti: raise CONFETTI_PIECES. Bigger pieces: widen random(6, 12). Higher burst: random(-16, -5) to random(-24, -8).
  • Counter position: in draw, current.rimY - 24 is 24 dots above the rim. Use a fixed spot like 60 to put it at the top.
  • Gentler shakes for everyone: in shakeBowl, change the 1.5 default and the 3 maximum.

Add a slider

Example: a slider for the time between balls. Every slider is one line in the lists in section 9: [setting, label, lowest, highest, step]. Change the stage size

The stage is 800 × 800 dots, and that number is in four places: SIZE = 800 in section 1, width="800" height="800" on the canvas, viewBox="0 0 800 800" on the SVG, and Width: 800, Height: 800 in buildWidgetFile. For a wide stage, say 1600 × 800: set the canvas to width="1600" height="800" and the SVG to viewBox="0 0 1600 800"; split SIZE into WIDTH = 1600 and HEIGHT = 800 and use the right one in each place (clearRect(0, 0, WIDTH, HEIGHT), the "fell off the bottom" checks use HEIGHT, toStage clamps x to WIDTH and y to HEIGHT); change the CSS #stage-box size from 100vmin square to width: 100vw; height: 50vw;; and set the OBS source to 1600 × 800. For a simple size change in OBS, you don't need any of this: just resize the source, since the canvas stretches.

Remember viewers differently

Followers are remembered by username, in lower case. Someone who renames themselves counts again. Event commands can pass $userid instead of $username; it's Mix It Up's own permanent id for that viewer, and addFollower works the same with it. To forget everyone, type followers.clear(); saveState(); in the overlay's console.

Part 5. Troubleshooting

First stop for any problem: the console. For the overlay in OBS, right-click the source → Interact doesn't show the console, so open the same widget link in Chrome, press F12 → Console, and look for lines starting [bowl] and red errors. Remember Chrome's count is separate from OBS's.

Balls fall through the bowl

  • A gap in the outline: balls escape where two points are far apart and the line cuts across empty space. Check the outline in the editor: it should follow the inside of the bowl closely, from rim to rim.
  • The outline is on the wrong edge: walls go on the outside of your line. Trace the inside surface of the bowl, not its outer edge.
  • Points drawn back and forth: if the line crosses itself, "outside" is confused. Clear it and draw it again in one sweep.
  • Very small balls with high gravity: tiny, fast balls can still squeeze through. Make balls bigger, gravity lower, or raise WALL.

Nothing happens when someone follows (or subs, or cheers)

  • Is the widget enabled in Overlay Widgets, and is Services → Overlay connected?
  • Are the event boxes (Follows, Twitch Subscriptions, Twitch Bits, Chat Messages) ticked on the widget, or are your event commands set up? (Not both.)
  • Follows: Mix It Up only reports someone's first follow each time it's opened, and the bowl only counts a name once, ever. Test with a chat command instead: !addballs 3 (MIXITUP_SETUP.md, Step 3).
  • Event commands: is the Function Name spelled exactly, with the same capitals (addBalls, not AddBalls)? Is the right widget chosen? Is the parameter value a real special identifier? A misspelt one arrives as plain text, and the console shows addBalls ignored.
  • Is the OBS source showing the widget's own link (Single Widget URL), at 800 × 800?

Balls count twice

  • Two copies are running: the bowl is in OBS twice (two browser sources), or there are two Twitch Bowl widgets in Mix It Up. Use one source (add it to other scenes with Add Existing) and delete old widgets.
  • Both widget events and event commands are on. Untick the widget's event boxes, or delete the event commands.
  • Gifted subs only: Settings → Commands → Mass Gifted Subs Filter Amount is switched off. Switch it on (1).

Settings didn't carry over to OBS

  • Editing in Chrome doesn't change OBS by itself. After editing, press Copy for Mix It Up and paste into the widget's HTML tab, then Save. (Or download and import the widget again, then delete the old one and update OBS's link.)
  • Pasted into the wrong tab? Everything goes in HTML. CSS and Javascript stay empty.
  • Pasted only part of it? In the HTML tab press Ctrl+A before pasting, so the old version is fully replaced. The text should start with <!doctype html>.
  • Still the old bowl? In OBS, select the source and press Refresh in its properties.

The count reset to zero

  • The count lives in OBS's browser storage for Mix It Up's address (localhost and its port). Changing Mix It Up's overlay port, or clearing OBS's browser cache, starts a fresh notebook.
  • You pressed Empty the real bowl before making the copy you pasted. That's what it's for, and it only happens once.

The editor opens instead of the bowl (or the other way round)

Add #overlay or #edit to the end of the address. In OBS, if you add bowl.html as a local file source instead of using Mix It Up's link, it shows the overlay but gets no events. Use the widget link.

"Couldn't save in this browser"

Browser storage holds about 5 MB per site, and big pictures fill it. Use smaller pictures (or pictures with fewer details), delete bowls you don't need, and press Save a copy straight away so nothing is lost.

The bowl breaks too early or too late

Type your own number in Breaks at, or switch to when the pile reaches the top. The suggested number comes from the outline's area and the ball size, so it changes when you redraw the outline or change Ball size.

No sound

Check Sound volume isn't 0 in the editor (and that you copied the widget again after changing it). In OBS, open the source's properties and tick Control audio via OBS, then check its level in OBS's audio mixer isn't muted. In the editor's test view, sounds start after your first click on the page; browsers don't allow sound before that.

Names show as something odd, or not at all

Names come from Mix It Up: the widget's events send them by themselves, and event commands need the user parameter ($username). Names only show on new balls, for 4 seconds. Untick Show who sent each ball to hide them.

Nothing runs in Mix It Up when the bowl breaks

Check Services → Developer API is connected, and that the Command ID in the editor is right: open http://localhost:8911/api/v2/commands?pageSize=500 while Mix It Up is open and compare. The ID has to be in the copy that's in Mix It Up, so copy the widget again after setting it.
